Java 线程池：七个参数与执行流程（面试必背）

Tianziyu-coder2026-03-282026-10-20

七个核心参数

执行流程（背这段就够）

  1. 线程数 < corePoolSize → 新建核心线程执行；
  2. 线程数 ≥ 核心数 → 进队列排队；
  3. 队列满了 → 线程数 < maximumPoolSize → 新建非核心线程；
  4. 队列满 + 线程数到上限 → 触发拒绝策略。

口诀：核心 → 队列 → 扩容 → 拒绝。注意是”先排队再扩容”，不是”先扩容”。

四种拒绝策略

策略 行为
AbortPolicy（默认） 抛 RejectedExecutionException
CallerRunsPolicy 由提交任务的线程自己执行（降速）
DiscardPolicy 静默丢弃
DiscardOldestPolicy 丢掉队列里最老的任务，再尝试提交

为什么不用 Executors 创建

阿里规约明确禁止：Executors.newFixedThreadPool 用的 LinkedBlockingQueue 容量是 Integer.MAX_VALUE，任务堆积会导致 OOM；newCachedThreadPool 最大线程数是 Integer.MAX_VALUE，线程爆炸。所以必须手动 new ThreadPoolExecutor。

参数怎么定

  • CPU 密集型：核心数 = CPU 核数 + 1
  • IO 密集型：核心数 = CPU 核数 × 2（或更大，取决于阻塞比例）
  • 队列必须有界（ArrayBlockingQueue 或指定容量的 LinkedBlockingQueue）
  • 线程工厂里给线程起名字，出问题时 jstack 一眼看出来

面试延伸

  • 线程池状态：RUNNING / SHUTDOWN / STOP / TIDYING / TERMINATED；
  • shutdown() 不再接新任务、等已提交的跑完；shutdownNow() 中断线程、返回未执行任务；
  • 核心线程默认也会回收（allowCoreThreadTimeOut(true) 可以打开）。
