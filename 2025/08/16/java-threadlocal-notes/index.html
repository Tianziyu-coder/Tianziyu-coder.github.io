ThreadLocal 原理、内存泄漏与异步场景下的上下文传递

Tianziyu-coder2025-08-162026-11-12

一句话总结

ThreadLocal 不是”给变量加线程安全”，而是每个线程持有自己的一份副本。它的存储挂在 Thread 对象上的 ThreadLocalMap 里；key 是弱引用，value 是强引用，线程池场景下不 remove() 就会内存泄漏并串数据。

一、它到底存在哪

关键：数据不在 ThreadLocal 对象里，而在线程自己的 Map 里，以 ThreadLocal 实例为 key。所以：

  • 一个 ThreadLocal 变量在不同线程里对应不同 value；
  • 线程结束，Map 随之可回收；
  • 线程不结束（线程池复用），value 会一直留在这个线程上。

二、为什么弱引用还会内存泄漏

如果 ThreadLocal 实例失去了外部强引用（比如局部 new 出来用完了），GC 会回收它，Entry 的 key 变成 null，但 value 仍被 Entry 强引用着，而 Entry 又被长期存活的线程池线程引用。于是 value 永远取不到、也回收不掉——这就是所谓的泄漏。

ThreadLocalMap 在 get/set/remove 时会顺路清理 key 为 null 的陈旧 Entry（expungeStaleEntry），但这是被动触发：如果之后这个线程再不碰 ThreadLocal，清理就不会发生。

所以正确姿势只有一条：用完 remove()，放在 finally 里。

面试常问”key 为什么设计成弱引用”：这是为了在 ThreadLocal 本身已无用时至少让 key 能被回收、给 Map 一个发现”这个 entry 已废弃”的机会；它并不能自动回收 value，所以仍要手动 remove。

三、典型用途

场景 怎么用
登录用户上下文 拦截器 set，finally remove，Service 层随处 get
链路追踪 traceId 日志 MDC 底层就是 ThreadLocal
事务 / 连接绑定 Spring TransactionSynchronizationManager 把 Connection 绑到线程
分页参数透传 PageHelper 用 ThreadLocal 存 page 信息
非线程安全对象复用 SimpleDateFormat 每线程一份

Spring 的 RequestContextHolder、SecurityContextHolder 也都基于它，所以异步线程里拿不到登录用户是同一个原因，不是框架 bug。

四、父子线程与线程池

InheritableThreadLocal 在创建子线程时把父线程的 Map 复制一份，能实现一次性传递。但线程池里线程是复用的：

  • 线程早就创建好了，不会再走”创建时复制”；
  • 上一个任务遗留的 value 可能被下一个任务读到，造成数据串味（用户 A 的上下文被用户 B 的请求看到）。

解决思路：

生产项目更常用阿里的 TransmittableThreadLocal（TTL），包装线程池后由框架负责捕获/回放/恢复。CompletableFuture、 @Async、MQ 消费者线程都要按这个思路处理。

五、面试怎么答

  • ThreadLocal 原理？ → 每个 Thread 持有 ThreadLocalMap，以 ThreadLocal 弱引用为 key 存 value；get/set 操作的是当前线程的 Map，因此天然线程隔离。
  • 为什么会内存泄漏？ → 线程池线程长期存活，key 被 GC 后 value 仍被强引用且无法访问；被动清理不保证及时，必须 remove。
  • ThreadLocal 和 synchronized 区别？ → 前者用”各存一份”避免共享，空间换时间；后者用”同一时刻只让一个线程访问”串行化，时间换空间。
  • 异步怎么传上下文？ → InheritableThreadLocal 在线程池下失效，需显式传递 + 清理，或用 TTL。

六、踩坑清单

  1. remove() 一定放 finally，业务抛异常也不能漏；
  2. 别把大对象、集合、Connection 长期挂在 ThreadLocal 上；
  3. static final 声明 ThreadLocal 实例，避免每次 new 导致 key 不同；
  4. 拦截器/Filter 里 set 了，就必须有对应的清理点，别只依赖框架；
  5. 用 ThreadLocal.withInitial 时别以为它会替你回收；
  6. 子线程、@Async、定时任务、MQ 消费者里默认没有 Web 请求的上下文，取不到值先查这条链路，别急着加全局静态变量。
