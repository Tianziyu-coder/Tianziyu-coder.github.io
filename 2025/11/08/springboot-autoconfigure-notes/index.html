Spring Boot 自动配置原理与手写一个 Starter

Tianziyu-coder2025-11-082026-11-12

一句话总结

@EnableAutoConfiguration 导入 AutoConfigurationImportSelector，它读取各 jar 里 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（Boot 2.7+ / 3.x，老版本是 spring.factories），拿到候选配置类，再用 @ConditionalOnXxx 过滤掉不满足条件的，剩下的才注册 Bean。

一、从启动类往下拆

@SpringBootApplication 是三个注解的组合：

注解 作用
@SpringBootConfiguration 本质是 @Configuration，标记启动类也是配置类
@ComponentScan 扫描启动类所在包及其子包下的组件
@EnableAutoConfiguration 通过 @Import(AutoConfigurationImportSelector.class) 开启自动配置

AutoConfigurationImportSelector 的核心链路：

  1. selectImports() → getAutoConfigurationEntry()；
  2. 用 ImportCandidates.load(...) 读取所有 jar 中 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports；
  3. 去重、按 @AutoConfigureBefore/After 与 @Order 排序；
  4. 排除 spring.autoconfigure.exclude 与 @SpringBootApplication(exclude=...) 指定的类；
  5. 把剩下的类名交给 Spring 当配置类解析，此时 @Conditional 条件才真正生效。

版本差异：Boot 2.6 及以前用 META-INF/spring.factories 里的 EnableAutoConfiguration 键；2.7 开始迁移到 .imports 文件，3.x 起只认新文件。迁移老 starter 时最常见的”配置不生效”就是文件名没换。

二、条件注解决定”配不配”

条件 判断依据
@ConditionalOnClass / MissingClass classpath 是否存在指定类
@ConditionalOnBean / MissingBean 容器里是否已有指定 Bean
@ConditionalOnProperty 配置项的值（havingValue、matchIfMissing）
@ConditionalOnResource 指定资源是否存在
@ConditionalOnWebApplication 应用类型

@ConditionalOnMissingBean 是 Spring Boot “约定优于配置，但用户可以覆盖“的关键：自动配置类通常在用户配置之后解析，所以你自己在 @Configuration 里定义一个 SmsClient，默认的就不会再注册。

注意：@ConditionalOnBean / MissingBean 只能用在自动配置类里，因为普通 @Configuration 的解析顺序不保证，条件判断可能早于目标 Bean 定义。

三、配置属性绑定

@EnableConfigurationProperties(SmsProperties.class) 负责把带 @ConfigurationProperties 的类注册成 Bean，并绑定 application.yml；宽松绑定支持 accessKey / access-key / ACCESS_KEY 多种写法。Spring Boot 2.2+ 也支持构造器绑定（配合 @ConstructorBinding），这样属性可以做成不可变对象。

五、面试怎么答

  • 自动配置是怎么触发的？ → @EnableAutoConfiguration → AutoConfigurationImportSelector 读 .imports / spring.factories → 排序排除 → 条件注解过滤 → 注册 Bean。
  • 为什么加个依赖就能用？ → jar 里带了自动配置类和注册文件，Spring Boot 启动时扫描所有依赖的该文件。
  • 怎么覆盖默认配置？ → 自己定义同类型 Bean（@ConditionalOnMissingBean 让位），或用配置属性/ @SpringBootApplication(exclude=...)。
  • spring.factories 和 .imports 区别？ → 版本迁移；新文件只列自动配置类，加载更快、语义更清晰，Boot 3.x 不再从 spring.factories 读自动配置。

六、踩坑清单

  1. starter 的自动配置类别放在业务方能扫描到的包下，否则会被 @ComponentScan 提前注册，绕过条件判断；
  2. 新项目一律用 AutoConfiguration.imports，别再抄老的 spring.factories 教程；
  3. @ConditionalOnClass 引用的类如果可能不存在，注解里用字符串 name = "com.xxx.X" 避免类找不到的连锁问题；
  4. 属性类要有 setter 或用构造器绑定，否则 access-key 永远是 null / 默认值；
  5. starter 里不要塞 application.yml、不要带版本冲突的 Spring 依赖，交给业务方统一管理；
  6. 启动类放在最外层包下，否则 @ComponentScan 扫不到自己的 Service，表现为”Bean 找不到”而不是自动配置问题。
