泛型擦除、反射与运行时注解：从编译期到运行期

泛型擦除、反射与运行时注解：从编译期到运行期

Tianziyu-coder2025-05-312026-11-12

一句话总结

Java 泛型是编译期特性：编译后类型参数被擦除到边界，运行时 List<String> 和 List<Integer> 是同一个类；但声明在类/字段/方法签名上的泛型信息会写进 Signature 属性，可以用反射读回来。

一、擦除规则与桥方法

规则：无界 T 擦成 Object；有界擦成第一个边界（多个边界时后面的靠插入强转实现）；编译器在必要处自动加强转，并生成桥方法保持多态不被破坏。

如果没这个桥方法，通过 Box 接口调用 set 会找不到实现——这就是擦除与多态冲突的修补方式，也是反射时看到”两个 set 方法”的原因（用 isBridge() 过滤）。

擦除带来的限制（面试高频）：

写法 是否合法 原因
new T() 否 运行时没有 T 的具体类型
new T[10] 否 数组需要确切组件类型
if (obj instanceof List<String>) 否 运行时无法区分参数化类型
List<int> 否 类型参数必须是引用类型，用 List<Integer>
重载 f(List<String>) / f(List<Integer>) 否 擦除后签名相同
List<String> ls = new ArrayList<Object>() 否 泛型不协变，要用通配符

二、PECS 与通配符

Producer Extends, Consumer Super：只往外读用 ? extends，只往里写用 ? super，两者都做就别用通配符。

List<?> 和 List<Object> 不一样：前者是”某种未知类型”，只能读成 Object、不能 add（除 null）；后者明确是 Object，什么都能放。

三、反射能拿回泛型信息吗

能，但只有声明处的签名（类、字段、方法返回值/参数上的泛型），拿不到 new ArrayList<String>() 这个局部变量的实际参数类型——因为它没被写进 class 文件。

原理：匿名内部类把 List<User> 写进了自己的父类签名，getGenericSuperclass() 因此能读到。这也是 TypeReference、TypeToken 必须写成匿名子类的原因。

反射实战要点：

  • getDeclaredXxx 只取本类声明的（含 private），getXxx 取所有 public（含继承）；
  • 反射调用有访问检查和方法查找开销，热路径上应缓存 Method/Field，或改用 MethodHandle / 编译期生成代码；
  • JDK 9 模块化之后，反射访问非公开成员可能抛 InaccessibleObjectException，需要模块 opens 或启动参数 --add-opens。

四、注解与自定义运行时注解

四个元注解：@Retention（生命周期）、@Target（能标在哪）、@Documented、@Inherited；JDK 8 又加了 @Repeatable。

RetentionPolicy 保留到 典型用途
SOURCE 源码 @Override、@SuppressWarnings、Lombok
CLASS class 文件（默认） 字节码增强、编译期工具
RUNTIME 运行时，可反射读取 Spring、MyBatis、自定义切面

在 Spring 项目里落地（拦截器或 AOP 二选一）：

注解本身只是元数据，不会有任何行为；行为来自读它的框架。这一点面试时常被问倒。

五、面试怎么答

  • 泛型擦除是什么？ → 编译期把类型参数替换成边界并插入强转，运行时不保留参数化类型，目的是兼容 JDK 5 之前的字节码。
  • 为什么 List<String> 不能赋给 List<Object>？ → 泛型不协变；否则可以通过 List<Object> 往里塞 Integer 破坏类型安全。数组是协变的，但会在运行时用 ArrayStoreException 兜底，两者设计不同。
  • 反射能不能拿到泛型？ → 声明签名可以（getGenericReturnType / getGenericSuperclass），局部变量不行。
  • 注解为什么能被 Spring 识别？ → @Retention(RUNTIME) 让注解在运行时可见，框架通过反射/AOP 读取并执行逻辑。

六、踩坑清单

  1. Arrays.asList(arr) 返回的是固定长度的内部 ArrayList，add/remove 会抛 UnsupportedOperationException；List.of(...) 完全不可变；
  2. Collections.emptyList() 也是不可变的，别往里 add；
  3. 基本类型数组传给 Arrays.asList 会得到 List<int[]> 而不是 List<Integer>；
  4. 反射 setAccessible(true) 在 JDK 17 下反射 JDK 内部类会失败，先考虑有没有公开 API；
  5. 自定义注解别忘 @Retention(RUNTIME)，否则运行时读不到，切面完全不生效；
  6. Optional、List<T> 这类泛型别当方法参数传 null，返回空集合/空 Optional 比 null 好处理。
